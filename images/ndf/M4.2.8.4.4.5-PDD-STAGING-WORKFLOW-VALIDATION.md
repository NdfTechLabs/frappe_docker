**Repository:** `NdfTechLabs/frappe_docker`

**Depends on:** Accepted M4.2.8.4.4.1–.4.4.4

## 1. Objective

Execute one controlled, staging-only Product Deployment Descriptor (PDD) publication on the real GitHub Actions/GHCR path. Validate that the direct PDD publication workflow can publish the immutable PDD OCI artifact, sign it with the exact GitHub OIDC identity, independently verify its signature and binding attestation through Cosign/Fulcio/Rekor, correlate the complete evidence bundle and upload that bundle for independent review.

This is an operational validation, not a policy promotion. The expected normalized decision remains:

```json
{
  "status": "rejected",
  "reason_codes": ["IDENTITY_POLICY_PROVISIONAL"]
}
```

A workflow run that collects valid cryptographic observations and publishes the correlated evidence is expected to succeed while preserving that rejected decision. It must never be described as a trusted publication.

## 2. Critical execution boundary

The PDD signer utility enforces the direct workflow identity:

`NdfTechLabs/frappe_docker/.github/workflows/ndf-publish-product-deployment-descriptor.yml@refs/heads/main`

It also requires the approved `workflow_dispatch` event and exact main-branch runtime context. Therefore:

- The accepted .4.4.4 implementation must first be present on `main` before the live PDD signing run.
- Do not attempt the live signer from `feat/M4.2.8`; it must fail the exact identity/runtime policy.
- Use one explicitly selected product image, not `all`.
- The source image workflow must use `publish=false`. This builds and validates a candidate staging image and runs the live source-image trust check without creating the official immutable product tag.
- Do not dispatch `ndf-publish-product.yml` with `publish=true`.
- The PDD publication workflow itself publishes a digest-pinned PDD OCI artifact to GHCR. Treat this as a staging validation artifact; do not add release promotion, official product-tag promotion or production-consumer rollout.
- Do not change the signer identity policy from provisional to confirmed.
- Do not bypass Rekor, certificate identity, issuer, workflow ref, source-SHA or evidence correlation checks.

If the accepted branch has not been merged to `main`, stop after confirming readiness; do not substitute a feature-branch run for the live identity observation.

## 6. Execute PDD publication, signing and verification

Dispatch **NDF / Publish Product Deployment Descriptor** from `main` using the exact values:

| Input | Value |
| --- | --- |
| `build_run_id` | Source image build run ID |
| `build_artifact_name` | Exact source build evidence artifact name |
| `verification_run_id` | PDD binding-verification run ID |
| `verification_artifact_name` | Exact PDD binding-verification artifact name |

The workflow must validate both upstream runs and exact artifact ownership, derive the source trust artifact, compare source predicate evidence, publish the PDD, validate its receipt, generate the binding Statement/predicate, then run the isolated `sign-pdd` job.

Expected signer observations:

1. The PDD immutable reference is derived from the validated publication receipt, not a caller-provided mutable tag.
2. Cosign v3.1.4 signs the exact PDD digest and attaches the PDD binding predicate.
3. Independent verification validates the signature and attestation with the exact certificate identity, issuer, workflow trigger, repository, ref and source SHA.
4. Normal Sigstore trusted-root and Rekor inclusion checks succeed; no tlog bypass is used.
5. The verified Statement subject and normalized result identify the exact receipt PDD repository/digest.
6. The verifier exits with the expected non-zero status only because the signer identity policy is provisional.
7. The normalized result remains rejected solely for `IDENTITY_POLICY_PROVISIONAL`.
8. Evidence correlation validates all seven bundle files and their manifest hashes before upload.
9. The workflow uploads `ndf-pdd-trust-evidence-<build_run_id>-<publication_run_attempt>` with 90-day retention and writes the explicit provisional rejection to the run summary.

A failed publication/signing job, unexpected verifier exit, missing result, mismatched digest, unverified Rekor entry, correlation failure or absent evidence artifact is a failed staging run. Do not manually repair or regenerate files inside the evidence bundle and then treat it as the original run's evidence.

## 7. Independent evidence review

Download the evidence artifact from the exact PDD publication workflow run. Preserve the original downloaded bytes in a read-only review directory.

Verify the manifest and file inventory locally:

```bash
python images/ndf/scripts/correlate_pdd_trust_evidence.py \
  --evidence-dir /path/to/downloaded/pdd-trust-evidence \
  --verify-manifest
```

Then independently review:

- `pdd-publication-record.json`: receipt schema and immutable reference.
- `pdd-image-binding-statement.json`: Statement v1, exact subject digest and predicate type.
- `pdd-image-binding-predicate.json`: exact structural/canonical equality with the Statement predicate.
- `pdd-trust-verification-result.json`: positive signature, signer, transparency/Rekor and one verified attestation; exact rejected provisional decision.
- `pdd-verified-attestation.json`: raw Cosign verification output retained from the exact source-SHA-constrained verification pass.
- `pdd-verify.log`: complete verifier output and exact expected provisional-policy rejection.
- `pdd-trust-evidence-manifest.json`: publication workflow/run identity, source build identity, descriptor, PDD digest, verification metadata and SHA-256/size inventory.

Compare the immutable PDD reference and digest across the receipt, Statement subject, normalized trust result and verified attestation. Confirm the manifest inventory covers every required non-manifest evidence file and that no unexpected file is present.

The standalone manifest check proves the downloaded files match the published manifest; it does not independently re-run Cosign verification. Review the raw Cosign output and normalized result as separate evidence.

## 9. Failure handling

- If source image build fails, stop; do not dispatch binding verification.
- If source `sign-trust` fails or its artifact is absent, stop; do not dispatch PDD publication.
- If PDD binding verification fails, stop; do not dispatch PDD publication.
- If PDD publication or signing fails for any reason other than the exact expected provisional-policy rejection, preserve logs and investigate before retrying.
- If correlation or upload fails, the run is not accepted even if Cosign operations appeared successful.
- If the signer identity check fails because the workflow is not running from the exact direct workflow on `main`, do not weaken the check; correct the dispatch context.
- If the policy unexpectedly returns `trusted`, stop and investigate. Do not interpret this as automatic policy confirmation.

## 10. Scope boundary

This run validates the producer-side PDD publication and evidence chain only. It does not implement or accept M4.2.8.4.5 independent consumer verification, does not promote an official product image tag, does not authorize production release, and does not confirm the PDD signer identity policy.
