# M4.2.8.4.5.2 — Self-contained Cosign Verification Primitives

**Repository:** `NdfTechLabs/frappe_docker`  
**Implementation branch:** `feat/M4.2.8.4.5-independent-consumer-verification`  
**Parent:** M4.2.8.4.5 — Independent PDD Consumer Verification  
**Depends on:** M4.2.8.4.5.1 — Independent PDD Consumer Verification Contract  
**Status:** Implementation contract; code and tests not yet accepted  
**Date:** 16 November 2026

## 1. Objective

Extend the existing PDD and product-image Cosign verifiers with an explicit self-contained consumer mode. In this mode, the verifier obtains the attestation Statement from Cosign's cryptographically verified registry output and validates it against the NDF schemas and trust contract without requiring a producer-side expected-predicate file.

This is a narrowly scoped consumer capability. Existing producer-side verification must retain its expected-predicate comparison and must not silently become self-contained.

## 2. Existing implementation findings

### 2.1 PDD verifier

`images/ndf/scripts/cosign_pdd_trust.py::verify_pdd` currently requires `expected_predicate_path`, extracts the first verified Statement, compares its predicate with the local expected predicate, then repeats signature and attestation verification using the exact source commit claimed by the verified Statement. It already validates the Cosign Statement v0.1 compatibility schema and applies the explicit `_type`-only normalization for semantic Statement v1 validation. It also preserves the second-pass attestation output.

### 2.2 Product-image verifier

`images/ndf/scripts/cosign_image_trust.py::verify_image` accepts an optional `expected_predicate_path` in its Python signature but currently raises when it is absent. It validates the NDF provenance Statement and repeats verification with the exact source commit. However, it writes `attestation_output` from the preliminary first pass rather than the exact-source-SHA second pass.

### 2.3 Security boundary

Neither verifier may trust an unverified payload, a local producer artifact, or a caller-supplied source SHA. The source SHA must be extracted from the first cryptographically verified and schema-valid Statement, then enforced as a certificate claim during the second verification pass.

## 3. Required API and CLI behavior

Add an explicit Boolean `self_contained: bool = False` parameter to both `verify_pdd` and `verify_image`.

- When `self_contained=False`, preserve current producer behavior: an expected predicate path is mandatory and the verified predicate must exactly equal that file.
- When `self_contained=True`, an expected predicate path must not be required. The verifier validates the complete verified Statement and predicate against the existing versioned schema, exact predicate type, immutable subject digest, workflow claims and source-SHA constraints.
- If an expected predicate path is supplied in self-contained mode, reject it rather than ambiguously mixing producer and consumer modes.
- If no expected predicate path is supplied while self-contained mode is false, fail closed with a clear error.
- Add a `--self-contained` flag to each `verify` CLI command and make `--expected-predicate` optional at argument parsing time. Runtime mode checks remain authoritative.
- Keep all existing signing behavior and producer workflow invocation semantics unchanged.

## 4. Verification invariants

Both verifiers must continue to:

1. Require a fully qualified immutable `repository@sha256:<64 lowercase hex>` reference; reject tags and mutable references.
2. Require Cosign exactly `v3.1.4`.
3. Load the existing shared identity policy and require the exact direct workflow identity and OIDC issuer.
4. Verify the artifact signature and attestation using normal Cosign/Sigstore verification, including trusted-root and Rekor checks. Do not add insecure flags or bypass claim checks.
5. Require the exact workflow trigger, repository, ref, certificate identity and issuer from the policy.
6. Extract exactly one verified in-toto Statement; reject missing, malformed, duplicate or ambiguous Statements.
7. Validate the complete Cosign Statement v0.1 compatibility schema, then normalize only `_type` to Statement v1 for NDF semantic validation. No other field may be modified, dropped, defaulted or normalized.
8. Validate the exact predicate type and one-element subject, including repository and digest equality with the immutable artifact reference.
9. Validate the complete NDF predicate schema, including all required provenance/binding fields and exact workflow path/ref/repository.
10. Derive the source commit from the validated Statement; require a valid full commit SHA and repeat both signature and attestation verification with that exact SHA as a certificate constraint.
11. Require the second-pass verified Statement to be semantically identical to the first-pass verified Statement.
12. Write normalized verification result evidence even when cryptographic checks pass but the shared identity policy remains provisional. The decision must remain `rejected / IDENTITY_POLICY_PROVISIONAL`; never represent it as trusted.

### 4.1 PDD-specific invariants

- Predicate type: `https://ndftechlabs.com/attestations/pdd-image-binding/v1`.
- Source SHA claim: `predicate.workflow.source_commit`.
- Validate the complete `pdd-image-binding-v1` predicate contract through `artifact_trust.validate_pdd_binding_statement`.
- Validate the PDD subject repository/digest against the supplied immutable PDD reference.
- Preserve the explicit Cosign v0.1 compatibility schema and `_type`-only normalization.

### 4.2 Product-image-specific invariants

- Predicate type: `https://slsa.dev/provenance/v1`.
- Source SHA claim: `predicate.ndf_build.workflow.source_commit`.
- Validate the complete NDF image provenance contract through `artifact_trust.validate_image_provenance_statement`.
- Validate the image subject repository/digest against the supplied immutable image reference.
- Preserve the explicit Cosign v0.1 compatibility schema and `_type`-only normalization.

## 5. Exact attestation output

For both verifiers, `attestation_output` must contain the raw stdout from the **second** `cosign verify-attestation` invocation, the one constrained by the exact source SHA extracted from the verified Statement.

Do not write preliminary first-pass output. Do not reserialize or normalize the raw Cosign output before preserving it. This output is evidence of the exact-source-SHA verification pass.

## 6. Trust result and error behavior

- Preserve the existing normalized result schema.
- A cryptographically valid result under the provisional policy must be written with `decision.status = rejected` and `decision.reason_codes = [IDENTITY_POLICY_PROVISIONAL]`.
- Preserve the current exception behavior for provisional policy in these primitives so existing producer callers are not silently changed. Consumer orchestration will later catch only this exact expected provisional rejection after validating the written result.
- Any Cosign failure, identity mismatch, issuer/event/repository/ref/source-SHA mismatch, Rekor failure, malformed Statement, schema violation, wrong subject/digest, or output-write failure remains a hard technical failure.
- Never turn an unexpected policy state or unexpected decision into an accepted result.

## 7. Required tests

Add or extend focused tests for both verifiers:

1. Existing producer mode still requires an expected predicate and rejects exact predicate mismatch.
2. Self-contained mode succeeds through all cryptographic/structural stages without a local expected-predicate file when policy is confirmed.
3. Self-contained mode rejects a simultaneously supplied expected-predicate file.
4. Complete Statement and NDF predicate validation still runs in self-contained mode.
5. Wrong subject repository, digest, predicate type, workflow path/ref/repository or malformed source SHA fails.
6. Wrong certificate identity, issuer, event, repository, ref or exact source SHA fails through the verification arguments.
7. Cosign version mismatch, signature failure, attestation failure, malformed payload, missing/duplicate Statement and invalid schema fail closed.
8. Statement v0.1 compatibility accepts only the explicitly supported envelope and does not normalize any field other than `_type`.
9. The second-pass Statement must equal the first-pass Statement.
10. Image and PDD `attestation_output` contain the exact second-pass stdout, not preliminary output.
11. Provisional policy writes the normalized rejected result and raises the expected provisional-policy exception; no trusted result is emitted.
12. Existing producer workflow tests and call sites remain unchanged.

Use deterministic fake runners to assert exact command ordering and arguments, including source-SHA-constrained second-pass verification. Do not make network calls in unit tests.
