## 1. Objective

Integrate the full independent consumer implemented in M4.2.8.4.5.3 into the existing manual PDD fetch workflow:

`.github/workflows/ndf-fetch-product-deployment-descriptor.yml`

The workflow must retrieve the publication receipt, invoke the normal full-consumer CLI, retain the consumer report and all independent trust evidence, and make the distinction between successful technical execution and artifact trust explicit.

This package changes only the consumer workflow and its static workflow-contract tests. It does not change the Python trust implementation, signer identity policy, publication workflows, or deployment authorization.

## 2. Invocation contract

The workflow invokes `images/ndf/scripts/fetch_product_deployment_descriptor.py` without `--skip-image-binding` and supplies dedicated output paths inside the initially empty consumer output directory:

- `pdd-consumer-verification-report.json`;
- `pdd-trust-result.json`;
- `pdd-verified-attestation.json`;
- `image-trust-result.json`;
- `image-verified-attestation.json`.

The normal CLI path performs the existing descriptor/evidence binding and both independent self-contained Cosign trust verifications. The workflow does not supply expected predicate files or a caller-selected image reference.

## 3. Exit-code and trust-outcome handling

The CLI exit contract remains authoritative:

- **0:** both artifact identities are trusted under confirmed identity policy.
- **2:** technical, cryptographic, evidence and correlation checks completed, but both identities have exactly the expected `IDENTITY_POLICY_PROVISIONAL` rejection.
- **1 / other:** technical failure or unexpected trust outcome.

The shell captures the CLI exit code without allowing Bash's `errexit` behavior to discard the expected code 2. Only 0 and 2 proceed to report correlation. All other codes fail the workflow step.

The workflow then independently checks that the report records every required execution stage as passed, both artifacts have signature, signer and transparency verification flags set, all required cross-artifact correlations and evidence binding passed, deployment authorization remains not granted, and the report agrees with the captured exit code:

- exit 0 must agree with confirmed policy, two trusted artifact decisions, an empty top-level reason list and `deployment_authorization=not_granted`;
- exit 2 must agree with provisional policy, two rejected artifact decisions, the exact single reason `IDENTITY_POLICY_PROVISIONAL`, completed execution, passed evidence binding and `deployment_authorization=not_granted`.

A code 2 run is classified as `provisional_rejected`. The workflow job can complete its evidence-collection task successfully, but its summary explicitly states that the artifacts are **not trusted** and deployment is not authorized. A green workflow result must therefore not be interpreted as a trusted artifact decision.

## 4. Evidence retention and permissions

The attempt-scoped consumer artifact retains:

- the original publication receipt;
- the retrieved PDD and complete published evidence bundle;
- both schema-validated primitive trust-result JSON files;
- both exact second-pass verified attestation outputs;
- the complete versioned consumer verification report; and
- CLI stdout for diagnostic traceability.

The upload step uses `if: always()` so available evidence and diagnostics are retained when verification fails partway through. Missing files on an early failure are warnings rather than a reason to mask the original failure.

The workflow retains only these repository permissions:

- `actions: read`;
- `contents: read`;
- `packages: read`.

It does not receive `id-token: write`, package write, repository write or action write permissions. It does not sign or publish artifacts, mutate tags, update identity policy, promote production artifacts or authorize deployment.

## 5. Implementation record

The existing publication-run ownership checks, receipt artifact naming/attempt validation, GHCR authentication, ORAS retrieval setup and manual dispatch inputs are preserved.

The workflow now:

1. calls the full-consumer CLI with explicit output paths;
2. distinguishes exit 0, exact expected exit 2 and technical/unexpected failures;
3. validates the report's terminal execution state, policy status, both trust decisions, reason codes, evidence-binding result, required correlation booleans and deployment-authorization boundary against the CLI exit code;
4. retains the receipt, retrieved bundle, both primitive results, both exact attestation outputs, consumer report and CLI output in an attempt-scoped artifact, including on partial failure; and
5. writes an always-run summary that labels provisional rejection as **REJECTED**, not trusted, and not deployable.

Added `images/ndf/tests/test_pdd_consumer_workflow_contract.py` to assert the read-only permissions, full-consumer invocation, exit-code handling, report/evidence requirements, artifact retention and explicit rejection summary.
