# M4.2.8.2.4 — Adversarial Trust Validation Tests

**Branch:** `feat/M4.2.8`
**Status:** Accepted for local implementation and focused verification
**Date:** 15 November 2026

## Scope

This package extends the tests for `images/ndf/scripts/artifact_trust.py` and the M4.2.8 trust schemas. It exercises rejection paths for untrusted or ambiguous trust metadata without introducing signing, cryptographic verification, or production workflow changes.

## Coverage added

- Reject non-finite JSON constants, duplicate identity IDs and ambiguous duplicate certificate-identity/artifact-kind entries.
- Confirm that the candidate image and candidate PDD purposes may share a caller certificate identity when their artifact kinds are distinct.
- Reject invalid run identifiers/attempts, malformed reusable-workflow commit SHAs and unexpected reusable-workflow claims on direct workflows.
- Reject incorrect image-provenance and PDD-binding predicate types and malformed subject digests.
- Validate a consistent trusted verification-result fixture.
- Reject trusted results when signature, signer, transparency proof or attestation verification is false; when attestations are absent; when reason codes are inconsistent; or when the artifact reference is mutable.

## Security boundary

These tests validate policy structure, supplied signer claims, statement schemas and normalized verification-result consistency. They do **not** verify Cosign signatures, Fulcio certificate chains, OIDC token authenticity, Rekor inclusion proofs, or establish artifact trust cryptographically.

No production workflow was modified in M4.2.8.2.4.

## Exit decision

M4.2.8.2.1 through .2.4 are implemented and locally verified. **M4.2.8.2 — Trust Data and Validation Foundation is accepted and closed** for schema, policy, deterministic validation utility and adversarial test coverage.

The signer identity entries remain provisional until an actual signing run confirms the Fulcio certificate identity and reusable-workflow OIDC claims. Cryptographic signing and independent verification remain in the next work package.
