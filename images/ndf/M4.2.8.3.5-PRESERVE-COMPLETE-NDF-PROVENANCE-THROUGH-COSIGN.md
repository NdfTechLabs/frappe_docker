# M4.2.8.3.5 — Preserve Complete NDF Provenance Through Cosign Attestation

**Repository:** `NdfTechLabs/frappe_docker`  
**Branch:** `fix/M4.2.8.3.5-preserve-ndf-provenance`  
**Status:** Implementation committed; local validation and staging interoperability run pending  
**Date:** 15 November 2026  
**Depends on:** M4.2.8.3.1–3.4

## 1. Objective

Preserve the complete NDF SLSA Provenance v1 predicate, including the required `ndf_build` extension, when Cosign v3.1.4 creates and verifies the image attestation.

The NDF provenance contract remains Statement v1 and continues to be validated against `ndf-image-provenance-v1.schema.json`. This milestone does not downgrade or relax that contract.

## 2. Source-based finding

Cosign v3.1.4 `pkg/cosign/attestation/attestation.go` implements two materially different generation paths:

- `--type slsaprovenance1` selects `generateSLSAProvenanceStatementSLSA1()`, which parses the predicate through the generated SLSA protobuf representation. The observed live output omitted NDF's custom `ndf_build` extension.
- `--type https://slsa.dev/provenance/v1` is accepted by `ParsePredicateType()` as a predicate URI and selects the generic `generateCustomStatement()` path. For a non-`custom` URI, `customType()` preserves that URI. The generic path parses the supplied predicate as a JSON object and builds the statement without the specialized SLSA protobuf conversion.

The second path is the supported interoperability approach selected for this correction. It must be confirmed against the actual Cosign v3.1.4 live output before this milestone is accepted.

## 3. Signing and verification changes

The signing utility now invokes:

```bash
cosign attest --yes \
  --type https://slsa.dev/provenance/v1 \
  --predicate "$PREDICATE_FILE" \
  "$IMAGE_REF"
```

The verification utility uses the same explicit predicate URI with `cosign verify-attestation`. It no longer uses the `slsaprovenance1` alias.

The verifier now requires the original generated predicate file through `--expected-predicate`. Cosign v3.1.4 generic generation still emits a Statement v0.1 wrapper, so a separate strict `cosign-image-provenance-statement-v0.1.schema.json` compatibility schema validates that outer representation. After Cosign's verification command returns successfully, the verifier:

1. Extracts the in-toto statement payload from Cosign's verified output.
2. Requires the decoded predicate to equal the original NDF predicate object exactly under JSON semantic comparison.
3. Validates the decoded wrapper against the dedicated v0.1 compatibility schema, then validates a version-normalized copy against the existing NDF Statement v1 provenance schema. The original verified payload is not rewritten.
4. Enforces the exact SLSA Provenance v1 predicate type, image repository and immutable digest.
5. Repeats the same exact-identity Cosign verification pass and requires the second verified statement to equal the first.

The original predicate comparison is in addition to schema validation. Missing, added or modified predicate claims fail closed. No NDF extension is ignored or treated as optional.

## 4. Cryptographic and authorization boundaries

- DSSE signature verification remains Cosign's responsibility.
- NDF extracts payload content only after a successful `cosign verify-attestation` command.
- Normal Sigstore trusted-root and Rekor verification remain enabled; no transparency bypass flags are introduced.
- Exact certificate identity, OIDC issuer, workflow trigger, repository, ref and source-SHA constraints remain unchanged.
- The signer identity policy remains provisional.
- A provisional policy cannot produce an authorized trusted decision.
- The staging workflow remains restricted to one product, `workflow_dispatch` on main and `publish=false`.
- Official product tag promotion remains disabled for the staging observation.
- NDF signs only its own validated image digest; it does not sign DT Master-supplied candidate artifacts.

## 5. Regression coverage

The focused unit tests must prove:

- Signing passes the explicit SLSA predicate URI and never the `slsaprovenance1` alias.
- Verification uses the same explicit URI.
- Verification requires the original predicate file.
- An unchanged complete predicate, including `ndf_build`, passes semantic equality.
- Any changed NDF claim, including composition hash, fails exact predicate comparison.
- Existing subject digest, repository, schema, identity, issuer, workflow claims, transparency and provisional-policy checks remain enforced.
- The live workflow supplies the original predicate file to the verifier.

Tests use a mocked Cosign runner and do not establish real OIDC, Fulcio, Rekor or GHCR interoperability.
