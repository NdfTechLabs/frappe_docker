# M4.2.8.3.5 — Preserve Complete NDF Provenance Through Cosign Attestation

**Repository:** `NdfTechLabs/frappe_docker`
**Implementation branch:** `fix/M4.2.8.3.5-preserve-ndf-provenance`
**Status:** **Complete and accepted — 16 November 2026**
**Depends on:** M4.2.8.3.1–3.4

## 1. Objective

Preserve the complete NDF SLSA Provenance v1 predicate, including the required `ndf_build` extension, when Cosign v3.1.4 creates and verifies the image attestation.

The canonical NDF provenance contract remains in-toto Statement v1 and continues to be validated against `ndf-image-provenance-v1.schema.json`. This correction does not downgrade or relax that contract.

## 2. Source-based finding

Cosign v3.1.4 implements materially different generation paths:

- `--type slsaprovenance1` selects a specialized SLSA protobuf conversion path. The observed live output omitted NDF's custom `ndf_build` extension.
- `--type https://slsa.dev/provenance/v1` is accepted as an explicit predicate URI and selects the generic JSON path. This preserves the supplied predicate but emits an in-toto Statement v0.1 wrapper.

The explicit predicate URI is therefore required for complete NDF provenance preservation with the pinned Cosign release.

## 3. Implementation

- Replaced the `slsaprovenance1` alias with the explicit SLSA Provenance v1 predicate URI for signing and verification.
- Added mandatory original-predicate input to the verification CLI and staging workflow.
- Added `cosign-image-provenance-statement-v0.1.schema.json`, a strict compatibility schema for Cosign's verified wrapper. The canonical NDF Statement v1 schema remains unchanged.
- Added exact decoded-predicate comparison against the original generated predicate.
- Validates the verified v0.1 wrapper, then validates a version-normalized copy against the canonical NDF v1 schema. The verified payload is not rewritten.
- Retains exact subject repository/digest, predicate type, signer identity, issuer, workflow claim, source-SHA and transparency checks.
- Added regression tests for explicit predicate URI use, mandatory expected predicate input, complete `ndf_build` preservation and rejection of altered claims.
