## 1. Purpose and acceptance boundary

This review maps the twelve M4.2.7 milestone criteria (CAND-01 through CAND-12) to implementation evidence and records the remaining local and external gaps.

Three evidence classes must remain distinct:

1. **Unit/local contract evidence:** repository tests, deterministic fixtures and script-level validation.
2. **Workflow composition evidence:** static checks of the GitHub Actions dependency graph, inputs/outputs, permissions and stage contracts. This does not execute the workflow.
3. **Operational evidence:** a real GitHub Actions run using the DT Master-produced OCI artifact and the configured DT Master GitHub App actor. This remains externally blocked and deferred.

A green unit suite or static workflow check must not be described as a real image/PDD publication or cross-repository integration run.

## 6. Accepted architecture decisions — Marketplace App Descriptors

The following decisions were agreed on 2026-11-15. They clarify ownership and future integration boundaries; they do not authorize changes to the current candidate schema or implementation of a descriptor registry in M4.2.7.

1. **Authority:** DT Master is the sole authority for Marketplace App Descriptor lifecycle and publication.
2. **Internal storage and publication:** DT Master may create, review, approve, version and retain descriptors internally, then publish approved immutable OCI descriptor artifacts when needed by a build candidate. A descriptor does not need to be publicly or externally published merely because it exists or is edited.
3. **Immutability:** Every published descriptor artifact is content-addressed and immutable. A changed descriptor is published as a new artifact with a new digest; an existing digest must never resolve to different content.
4. **NDF consumption:** NDF retrieves and verifies published descriptor artifacts. NDF does not create or maintain a competing authoritative Marketplace descriptor registry.
5. **Independent build acceptance:** NDF remains responsible for deciding whether an application, its source, dependencies and requested composition satisfy NDF build and runtime policies. Publication by DT Master is not automatic build approval.
6. **Retirement and historical evidence:** Descriptor retirement governs future use according to the agreed policy; it must not invalidate or destroy descriptor content required to verify historical candidates and completed builds. Referenced artifacts must remain retrievable for the applicable audit-retention period.
7. **OCI publication and consumption contract:** DT Master shall adopt the existing NDF Marketplace App Descriptor v1 schema (`images/ndf/schemas/marketplace-app-descriptor-v1.schema.json`) as the descriptor content contract. DT Master and NDF must agree on OCI artifact packaging and media types, publication and approval state, registry ownership and permissions, candidate-to-descriptor reference/digest binding, retrieval/verification, and retirement/retention semantics before implementing external descriptor artifact consumption. No new descriptor content schema is required for this integration.

### M4.2.7 boundary

The OCI descriptor registry and its producer/consumer integration are **DEFERRED / FUTURE CROSS-REPOSITORY WORK**, pending DT Master agreement. They are not a new M4.2.7 work package and are not required to be implemented in the NDF repository to close this milestone.

For the current M4.2.7 scope:

- Descriptor-backed applications continue to be checked against the existing local NDF descriptor catalogue.
- Legacy embedded manifest applications remain supported and are validated using the metadata and policies available to the existing resolver. Missing descriptor provenance is recorded as a limitation; descriptor metadata must not be fabricated.
- Newly created product and capability composition manifests must use schema v2. Existing v1 manifests remain supported until each is explicitly migrated, reviewed and accepted. This policy does not require a bulk migration during M4.2.7.
- The v2 composition manifest's repository-relative `descriptor` path remains distinct from the future external OCI `descriptor_ref` / digest binding. The OCI integration must not silently redefine the existing local path.
- The current candidate schema and adapter are not changed by this decision.
- Composition-hash recomputation remains deferred until DT Master and NDF agree on canonical serialization, field inclusion, normalization and versioning rules.

This decision does not change the existing M4.2.7 repository boundary: implementation changes in this milestone remain restricted to NDF. DT Master and DT Tenant remain read-only references.
