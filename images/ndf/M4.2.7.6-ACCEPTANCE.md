# M4.2.7.6 — End-to-End NDF Acceptance

**Repository:** `NdfTechLabs/frappe_docker`
**Branch:** `feat/M4.2.7`
**Status:** Acceptance plan and local test coverage in progress
**Parent work package:** M4.2.7 — Candidate-Driven CI/CD

## 1. Purpose

Verify that the NDF-owned candidate pipeline contracts compose correctly across candidate intake, candidate-to-lock adaptation, prepared-input image build handoff, image verification, PDD binding/publication and correlated result production.

This package validates NDF behavior using repository-owned fixtures, deterministic test doubles and workflow contract assertions. It does not claim live DT Master interoperability or a real GHCR/Docker publication when those external prerequisites are unavailable.

## 2. Acceptance boundary

M4.2.7.6 has two distinct evidence classes:

1. **NDF-local acceptance:** executable tests and static workflow checks against NDF-owned candidate fixtures. These can be completed on `feat/M4.2.7` without a DT Master producer or production dispatch identity.
2. **Cross-repository operational acceptance:** a real DT Master-produced OCI candidate, dispatch by the configured DT Master GitHub App actor, and a GitHub Actions run that publishes the image, PDD and attempt-specific result artifact. This remains deferred to the corresponding DT Master milestone that supplies those dependencies.

The second class is not a prerequisite for continuing the NDF-local work in this package. It must remain visible as a deferred integration acceptance item and must not be reported as passed.

The candidate workflow's main-branch and `NDF_MASTER_DISPATCH_ACTOR` authorization gates remain unchanged. Do not substitute a developer actor, weaken the gate, or treat a fabricated artifact as proof of producer compatibility.

## 4. Test implementation in this increment

The existing intake, adapter, prepared-input and candidate workflow tests provide the NDF-local coverage for NDF-ACC-01 through NDF-ACC-06 and NDF-ACC-10.

The result-writer acceptance suite is being expanded to cover:

- each required stage failing independently (dispatch gate, candidate preparation, image build/verification and PDD publication);
- missing image evidence despite successful upstream job conclusions;
- malformed lock evidence;
- malformed candidate payload hash;
- mismatched PDD reference and digest;
- distinct result identities for distinct workflow attempts;
- sanitized terminal failure output and existing output-overwrite protection.

The tests use deterministic fixtures and do not publish images or PDDs to GHCR.

```bash
actionlint

```

Record the final focused/full test counts, tool versions, commit SHA and any pre-commit formatting follow-up in this document and the M4.2 tracker. A first pre-commit run that modifies files is not final passing evidence; rerun all hooks after formatting changes.

## 6. Deferred operational acceptance

The live GitHub Actions candidate run remains deferred because the following prerequisites are not yet available:

1. DT Master has not yet published a real candidate OCI artifact conforming to the agreed producer contract.
2. The `NDF_MASTER_DISPATCH_ACTOR` repository variable has not yet been configured with the actual DT Master GitHub App actor identity.

When the corresponding DT Master milestone delivers both prerequisites, perform the real cross-repository run and verify:

- dispatch authorization by the configured GitHub App identity;
- exact candidate artifact reference, manifest digest and payload SHA-256;
- successful candidate intake and deterministic candidate-to-lock handoff;
- image staging digest and image verification evidence;
- PDD OCI reference, digest and content hash bound to the same image and candidate;
- `ndf-candidate-result-<run_id>-<run_attempt>` artifact upload;
- result JSON candidate, correlation, run/attempt, image, PDD, composition and lock bindings.

This is a deferred external integration test, not a failure and not a reason to stop the current NDF milestone sequence.

## 7. Exit criteria

M4.2.7.6 NDF-local acceptance is complete when NDF-ACC-01 through NDF-ACC-11 are evidenced and documented. EXT-ACC-01 remains explicitly deferred until its DT Master dependencies are available.

Closing M4.2.7 as a whole still requires the repository's normal review/merge process and completion of all applicable acceptance criteria. This document does not authorize M4.2.8.
