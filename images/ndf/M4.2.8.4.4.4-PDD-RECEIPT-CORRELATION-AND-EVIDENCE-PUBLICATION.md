# M4.2.8.4.4.4 — PDD Receipt Correlation and Durable Trust Evidence

**Repository:** `NdfTechLabs/frappe_docker`
**Branch:** `feat/M4.2.8`
**Status:** Implementation committed; local validation pending
**Date:** 16 November 2026
**Depends on:** Accepted M4.2.8.4.4.1 audit, .4.4.2 publication/signing job contract and .4.4.3 binding generation/Cosign integration

## 1. Objective

Make the PDD publication and signing workflow produce a durable, attempt-scoped evidence bundle that can be independently reviewed and consumed by the later staging and fetch-verification steps.

The evidence-correlation stage must prove that the publication receipt, immutable PDD OCI reference, binding Statement, predicate, normalized Cosign verification result and raw verified attestation all describe the same PDD publication and signing attempt. Missing, malformed, stale, cross-run, altered or internally inconsistent evidence must fail closed.

The signer identity policy remains provisional. A cryptographically successful verification with the exact normalized decision `rejected / IDENTITY_POLICY_PROVISIONAL` is the expected observation at this stage; it must never be represented as trusted.

## 2. Existing implementation baseline

The accepted .4.4.3 workflow currently:

- Publishes the PDD OCI artifact and writes `pdd-publication-record.json`.
- Generates `pdd-image-binding-statement.json` and `pdd-image-binding-predicate.json`.
- Uploads the attempt-scoped `ndf-pdd-signing-input-<build_run_id>-<publication_run_attempt>` artifact.
- Preserves the existing `ndf-pdd-publication-<build_run_id>-<publication_run_attempt>` receipt artifact.
- Runs the dependent `sign-pdd` job with the only `id-token: write` permission in this workflow.
- Writes `pdd-trust-verification-result.json`, `pdd-verified-attestation.json` and `pdd-verify.log` into the signer runner's temporary directory.
- Requires signature, signer, Rekor and attestation verification to succeed while the normalized decision remains rejected solely for `IDENTITY_POLICY_PROVISIONAL`.

The current workflow does not yet correlate these outputs into one durable evidence package or upload the signer outputs as an artifact. Temporary runner files are not durable evidence.

## 3. Evidence bundle contract

### 3.1 Required files

Create one attempt-scoped evidence directory and publish it as a single artifact named:

`ndf-pdd-trust-evidence-<build_run_id>-<publication_run_attempt>`

The bundle must contain:

| File | Source | Required validation |
| --- | --- | --- |
| `pdd-publication-record.json` | Exact receipt downloaded from the current run's signing-input artifact | Validate with `pdd-publication-record-v1.schema.json` |
| `pdd-image-binding-statement.json` | Exact Statement generated by .4.4.3 | Validate Statement and PDD binding schema; subject repository/digest must equal receipt |
| `pdd-image-binding-predicate.json` | Exact predicate generated by .4.4.3 | Must equal Statement predicate structurally and canonical bytes |
| `pdd-trust-verification-result.json` | Output of `cosign_pdd_trust.py verify` | Validate with `artifact-trust-verification-result-v1.schema.json` and enforce the exact expected provisional decision |
| `pdd-verified-attestation.json` | Raw stdout captured from successful Cosign attestation verification | Preserve exact bytes; require non-empty and ensure the trust utility has successfully parsed and validated the envelope |
| `pdd-verify.log` | Complete verifier stdout/stderr | Preserve exact bytes; must include the exact provisional-policy rejection message |
| `pdd-trust-evidence-manifest.json` | Generated by the correlation utility | Validate against the new evidence-manifest schema; contains workflow/run identity, artifact identity, correlated digest and SHA-256 for every other bundle file |

Do not include registry credentials, OIDC tokens, environment dumps, GitHub tokens, signing keys or unrelated runner files. Do not re-fetch or regenerate the PDD Statement after signing; preserve the exact files that were signed and verified.

### 3.2 Correlation invariants

The correlation utility must fail unless all of the following hold:

1. The publication receipt validates against its existing schema.
2. The trust result validates against the existing normalized trust-result schema.
3. The PDD reference is exactly `receipt.artifact.repository@receipt.artifact.digest` and equals `receipt.artifact.immutable_reference`.
4. The trust result has `artifact.kind == "pdd"`; repository, digest and immutable reference exactly equal the receipt.
5. The Statement is a valid in-toto Statement v1 with the expected PDD binding predicate type and exactly one subject.
6. The Statement subject repository and SHA-256 digest equal the receipt repository and digest.
7. The predicate file equals `statement.predicate` structurally and in NDF canonical serialization.
8. The trust result records `signature.verified == true`, `signer.verified == true`, `transparency.verified == true` and `transparency.log_entry_verified == true`.
9. There is exactly one verified PDD binding attestation; its predicate type is exact, its subject digest equals the receipt digest, and its `predicate_sha256` equals SHA-256 of the canonical predicate bytes.
10. The decision is exactly `{"status":"rejected","reason_codes":["IDENTITY_POLICY_PROVISIONAL"]}`. No additional reason code is allowed.
11. The verifier log records the exact expected provisional-policy rejection. Any other verifier error, absent result, or missing attestation is a hard failure.
12. The workflow run ID, run attempt, repository, workflow path, ref and source commit in the evidence manifest match the current GitHub Actions runtime context. The source build run ID and attempt embedded in the signing-input artifact name and publication receipt correlation are retained without substituting the publication workflow run ID.
13. Every manifest file digest is computed from the exact bytes included in the bundle. The manifest must not hash itself.

The correlation utility must use strict JSON parsing, reject duplicate JSON keys, validate schemas with the configured format checker and write outputs atomically. It must reject symlinks and paths outside the designated evidence directory.

### 3.3 Evidence manifest

Add a versioned schema, `images/ndf/schemas/pdd-trust-evidence-manifest-v1.schema.json`, and a generator/validator utility, `images/ndf/scripts/correlate_pdd_trust_evidence.py`.

The manifest must include:

- `schema_version: "1.0.0"`;
- evidence kind `pdd-publication-trust`;
- publication workflow repository, workflow path, ref, source commit, run ID and run attempt;
- source build run ID, source build attempt and exact signing-input artifact name;
- PDD descriptor ID, PDD repository, digest and immutable reference;
- normalized trust decision and reason codes;
- verification timestamp and Cosign version;
- a deterministic map of each required evidence filename to its SHA-256 and byte size.

The manifest is a correlation/index record, not a replacement for the signed Statement, normalized trust result, publication receipt or raw attestation. It must explicitly record that the observed decision is rejected due to provisional identity policy.

## 4. Workflow integration

Extend the existing `sign-pdd` job only:

1. Preserve the existing signing and verification commands and their expected-exit handling.
2. After the existing provisional-result validation, create the evidence directory and copy the exact receipt, Statement and predicate from the downloaded signing-input artifact.
3. Copy the normalized result, raw attestation output and complete verification log into the evidence directory.
4. Run the correlation utility to validate every cross-file invariant and generate the manifest.
5. Upload the complete directory with `actions/upload-artifact`, using the attempt-scoped name above and 90-day retention.
6. Add a concise GitHub step summary with the PDD immutable reference, descriptor ID, evidence artifact name, verification timestamp and explicit `REJECTED: IDENTITY_POLICY_PROVISIONAL` decision.
7. Never mark the workflow as a trusted publication. A successful job means the expected cryptographic observations were collected and correlated, not that policy accepted the signer.

Do not grant additional permissions. The evidence artifact is created by the existing signer job; no second OIDC-enabled job is permitted. Keep the existing receipt artifact unchanged.

## 5. Tests

Add focused tests for the correlation utility and expand the publication workflow contract tests.

Required adversarial cases include:

- receipt repository, digest or immutable reference mismatch;
- trust result for another artifact kind, repository, digest or immutable reference;
- Statement subject repository or digest mismatch;
- wrong Statement type or predicate type;
- predicate file structurally or canonically different from Statement predicate;
- missing, duplicate or unverified attestation;
- wrong attestation subject digest, predicate type or predicate hash;
- signature, signer, Rekor or transparency flag false;
- trusted decision, extra reason code or any decision other than the exact provisional rejection;
- missing/empty attestation or log file;
- missing or modified evidence file after manifest generation;
- wrong run ID, attempt, workflow path, ref, repository or source commit;
- duplicate JSON keys, symlinked outputs and path traversal;
- partial output cleanup and atomic-write failure.

Tests must use fixtures and mocked data only. They must not call GitHub, GHCR, Fulcio, Rekor or Cosign live services.

Workflow contract tests must assert that correlation runs after verification, upload runs only after successful correlation, the artifact name is attempt-scoped, retention is 90 days, the existing receipt artifact is preserved, no new permissions are granted, and the summary states the provisional rejection rather than trusted status.

## 6. Acceptance criteria

- All required evidence files are present in one attempt-scoped artifact.
- The manifest validates and hashes the exact included file bytes.
- Receipt, Statement, predicate, trust result and attestation are proven to identify one immutable PDD digest.
- Verification observations are cryptographically positive while the normalized policy decision remains exactly rejected for `IDENTITY_POLICY_PROVISIONAL`.
- Missing, stale, cross-run, altered, malformed or mismatched evidence fails closed before artifact upload.
- The evidence bundle is retained for 90 days and is discoverable from the publication workflow run.
- Existing receipt artifact naming/schema, source-trust intake and least-privilege job permissions remain unchanged.
- Focused tests, full NDF suite, compileall, pre-commit, actionlint and diff checks pass.

## 7. Explicit non-goals

- Confirming the PDD signer identity policy.
- Converting the expected provisional rejection into a trusted decision.
- Live GHCR/Fulcio/Rekor staging validation (.4.4.5).
- Independent consumer/fetch verification (.4.5).
- Production promotion, release gating or candidate signing.
- Changing the publication receipt schema or product-image trust contract.

## 8. Implementation checkpoint

Contract defined after review of the accepted .4.4.3 workflow. The current signer already writes the normalized result, raw verified attestation and verifier log, but does not upload them. The implementation should add a dedicated deterministic correlation utility and manifest schema, then integrate the bundle creation and upload into the existing `sign-pdd` job without changing its permission boundary.
