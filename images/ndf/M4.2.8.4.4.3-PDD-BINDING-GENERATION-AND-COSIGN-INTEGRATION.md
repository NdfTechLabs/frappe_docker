## 1. Objective

Integrate deterministic PDD binding generation and Cosign signing/verification into the existing direct PDD publication workflow. The publication job publishes the OCI artifact and emits the immutable digest receipt. It then generates the binding Statement v1 and exact predicate. A separate dependent signing job receives only the attempt-scoped signing input and performs keyless signature and attestation operations.

This step does not confirm the PDD signer identity policy. Verification is expected to produce the normalized provisional rejection while preserving successful cryptographic observations. Detailed correlation and evidence publication are completed in .4.4.4; live staging validation is .4.4.5.

## 2. Existing reusable components

- `generate_pdd_image_binding.py` validates the PDD, publication receipt, source-image Cosign verification result and source provenance predicate, then generates a deterministic Statement v1.
- `cosign_pdd_trust.py sign` signs an immutable PDD OCI digest and attaches the PDD binding predicate using pinned Cosign v3.1.4.
- `cosign_pdd_trust.py verify` independently verifies the signature and binding attestation against exact identity/issuer/workflow claims and compares the verified predicate with a locally generated expected predicate.
- The signer utility enforces direct workflow identity: `ndf-publish-product-deployment-descriptor.yml@refs/heads/main`.

The generator currently emits the Statement file. This work package adds an explicit atomic predicate output so the signing utility receives the exact predicate bytes from the same validated generation operation.

## 3. Required job architecture

### 3.1 Publication job

The existing `publish` job retains its current least-privilege permissions:

- `actions: read`
- `contents: read`
- `packages: write`

After the ORAS publication command successfully writes `pdd-publication-record.json`, it must:

1. Invoke the binding generator with the verified descriptor, publication receipt, exact source-image trust result and source-image provenance predicate.
2. Emit both `pdd-image-binding-statement.json` and `pdd-image-binding-predicate.json`.
3. Upload a unique attempt-scoped signing-input artifact containing the receipt, Statement and predicate.
4. Expose only the artifact name and immutable PDD reference as job outputs. The receipt remains authoritative; the signing job validates it again.

The existing receipt artifact name and schema remain unchanged.

### 3.2 Signing job

Add `sign-pdd` with `needs: publish`. It alone receives:

```yaml
permissions:
  actions: read
  contents: read
  packages: write
  id-token: write
```

The job must:

1. Check out the exact workflow commit from the current `main` dispatch.
2. Download the signing-input artifact from the current workflow run and attempt.
3. Validate the receipt schema and derive `repository@sha256:digest` from `artifact.immutable_reference`.
4. Confirm the receipt's immutable reference is exactly repository plus digest and that its digest is the same value represented in the generated Statement subject.
5. Install Cosign v3.1.4 using the pinned installer revision already used by the product-image trust workflow.
6. Authenticate to GHCR using the job-scoped GitHub token.
7. Run `cosign_pdd_trust.py sign` using the immutable receipt-derived reference, Statement and predicate.
8. Run `cosign_pdd_trust.py verify` independently against the same digest and predicate.
9. Preserve the normalized trust result and raw verified attestation output for the next evidence-correlation step.

The signing job must not sign a mutable tag, consume a caller-supplied PDD reference, or trust an unvalidated job output in place of the publication receipt.

## 4. Provisional identity policy

The identity `product-pdd-publication` remains provisional.

The verifier writes a normalized result with cryptographic signature, signer and Rekor verification observations set true, one verified PDD binding attestation, and:

```json
{
  "decision": {
    "status": "rejected",
    "reason_codes": ["IDENTITY_POLICY_PROVISIONAL"]
  }
}
```

The verification utility exits non-zero for this expected policy rejection. The workflow must not convert that rejection to trusted or mask arbitrary verification errors. .4.4.4 defines strict expected-exit handling and complete evidence correlation. Until that handling is implemented, the signing integration must not claim a successful trust decision.

## 5. Predicate output contract

Extend `generate_pdd_image_binding.py` with a required `--predicate-output` argument. Write the exact `statement["predicate"]` as canonical JSON using the established NDF canonicalization rules, atomically, after full validation and before reporting success.

Acceptance tests must prove:

- Statement and predicate are derived from one validated operation.
- Predicate output equals the Statement's `predicate` object exactly.
- Both outputs are deterministic across repeated runs.
- Neither output is left partially written on validation failure.
- A symlink output is rejected.
- The CLI requires the predicate output path.

## 6. Workflow and test requirements

Extend `test_pdd_publication_workflow_contract.py` to assert:

1. The publication job still has no OIDC permission.
2. Only `sign-pdd` has `id-token: write`.
3. `sign-pdd` depends on `publish` and is not unconditional.
4. The publication job generates both binding outputs only after the publication receipt exists.
5. The signing-input artifact is attempt-scoped and contains receipt, Statement and predicate.
6. The signer downloads only the current workflow run's artifact.
7. The signing subject is derived from the validated receipt's immutable reference.
8. Cosign v3.1.4 uses the pinned installer revision.
9. Both sign and verify commands invoke the PDD-specific utility.
10. No mutable tag, OIDC token, registry credential or secret is transferred through job outputs/artifacts.
11. Existing publication receipt artifact name/schema and upstream source trust checks remain intact.

Extend generator tests for predicate output and add focused mocked workflow integration tests for signing command order and immutable digest propagation. Do not call live GitHub, GHCR, Fulcio or Rekor from unit tests.

## 7. Acceptance criteria

- Generator emits deterministic Statement and predicate files from the same validated input set.
- Publication succeeds before binding generation and signing-input artifact upload.
- Signing job is the only PDD workflow job with OIDC permission.
- Signing job consumes the current run's attempt-scoped artifact.
- The immutable PDD reference is read from and validated against the publication receipt.
- PDD-specific Cosign sign and verify commands are run in the direct PDD workflow identity context.
- Tests prove least privilege, job ordering, digest binding, predicate equality and fail-closed behavior.
- Cosign remains pinned at v3.1.4; the signer identity remains provisional.
- Focused tests, full NDF tests, compileall, pre-commit, actionlint and diff checks pass before acceptance.

## 8. Explicit non-goals

- Confirming the PDD identity policy.
- Treating the expected provisional rejection as trusted.
- Consumer/fetch verification (.4.5).
- Live staging run (.4.4.5).
- Production promotion or candidate signing.
- Changing source-image trust policy or PDD publication receipt schema.
