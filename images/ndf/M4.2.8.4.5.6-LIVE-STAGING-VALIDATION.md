## 4. Acceptance checks

Accept the pre-merge staging exercise only if all of the following are demonstrated by the consumer run and its attempt-scoped artifact:

1. The workflow validates publication run `43853275916` and receipt artifact `ndf-pdd-publication-43847907267-1`.
2. PDD retrieval is by the receipt's immutable PDD reference and the retrieved OCI manifest digest matches the receipt.
3. The complete PDD and published evidence bundle is preserved, with descriptor validation and evidence binding passing.
4. The PDD signature and binding attestation are independently verified from Cosign's registry-returned output.
5. The source-image signature and SLSA provenance are independently verified from Cosign's registry-returned output at the exact source-image digest.
6. Both artifacts have `signature_verified=true`, `signer_verified=true` and `transparency_verified=true`; Rekor inclusion verification is not bypassed.
7. The consumer correlates the PDD descriptor, image repository, digest, platform, original image build source commit/run ID and canonical provenance predicate hash.
8. The report records technical execution `completed` and every required execution stage `passed`.
9. The exact trust outcome is `rejected`, with policy status `provisional_until_live_certificate_observation` and sole reason code `IDENTITY_POLICY_PROVISIONAL` for both PDD and source image.
10. Deployment authorization is exactly `not_granted`.
11. The workflow uploads the PDD receipt, retrieved PDD/evidence bundle, both primitive trust results, both verified attestation outputs, consumer report and CLI diagnostics.

A technical error, missing report, failed signature, signer or Rekor check, unexpected reason code, mismatched provenance hash, incomplete evidence, or inconsistent decision/exit code is a failure. Do not reinterpret it as the expected provisional rejection.
