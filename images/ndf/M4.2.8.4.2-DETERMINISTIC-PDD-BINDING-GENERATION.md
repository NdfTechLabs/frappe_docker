# M4.2.8.4.2 — Deterministic PDD Binding Statement Generation

**Status:** Implementation committed; local validation pending  
**Branch:** `feat/M4.2.8`  
**Date:** 16 November 2026  
**Depends on:** M4.2.8.4.1 accepted contract

## 1. Objective

Generate the existing PDD-to-image in-toto Statement v1 deterministically from a validated PDD, its immutable OCI publication receipt, a normalized source-image trust result, the verified source-image SLSA predicate and the actual GitHub Actions workflow context.

This step generates structured binding evidence only. It does not sign the PDD, perform Cosign verification itself, change workflows, confirm identity policy or authorize promotion.

## 2. Implementation

Added:

- `images/ndf/scripts/generate_pdd_image_binding.py`
- `images/ndf/tests/test_generate_pdd_image_binding.py`

The generator:

1. Calls the existing independent PDD validator before reading descriptor claims.
2. Validates the publication receipt against `pdd-publication-record-v1.schema.json`.
3. Cross-checks descriptor ID, schema version, canonical content hash, image repository/digest/platform, PDD artifact immutable reference and distinct PDD/image digests.
4. Validates the normalized trust result with `artifact_trust.validate_trust_verification_result`.
5. Requires the source image identity and immutable digest to match the PDD exactly.
6. Requires signature, signer, transparency, Rekor inclusion and exactly one verified SLSA Provenance v1 attestation to pass.
7. Hashes the supplied verified predicate using the same NDF canonical JSON serialization as `cosign_image_trust.py`: sorted keys, compact separators, UTF-8, `ensure_ascii=False`, and one trailing LF.
8. Requires the calculated predicate hash to equal the normalized trust result's `predicate_sha256`.
9. Cross-checks product, platform, source commit and source workflow run ID against the PDD.
10. Accepts a rejected trust decision only when its sole reason is `IDENTITY_POLICY_PROVISIONAL`. Any other rejection fails closed.
11. Requires the exact PDD publication workflow on `refs/heads/main`, `workflow_dispatch`, and valid run/source SHA context.
12. Emits and schema-validates the complete Statement v1 against `pdd-image-binding-v1.schema.json`, then writes stable formatted JSON atomically.

## 3. Inputs and CLI

Required inputs:

- `--descriptor`: validated `product-deployment.json`
- `--publication-record`: immutable PDD publication receipt
- `--source-trust-result`: normalized source-image verification result
- `--source-predicate`: predicate extracted from the independently verified source-image attestation
- `--statement-output`: destination for the generated Statement v1

The workflow context is read from the GitHub Actions environment. No workflow inputs may override those claims.

## 4. Trust boundary

The generator is a deterministic semantic validator and statement producer. It does **not** perform Cosign cryptographic verification, authenticate the normalized trust-result JSON, query Rekor, or retrieve the source attestation from GHCR.

The source trust result and predicate must therefore be outputs of the trusted source-image verification stage, correlated to the same immutable image digest. A caller-supplied predicate and caller-supplied JSON result are not independently authenticated by this generator. M4.2.8.4.3/.4.5 must provide the cryptographic verification and secure workflow handoff/retrieval that establish those inputs.

The generator does not treat `IDENTITY_POLICY_PROVISIONAL` as trust approval. It permits generation of a binding statement for staging evidence while the normalized trust decision remains rejected. Promotion remains prohibited.

## 5. Tests added

The focused tests cover:

- canonical JSON bytes including UTF-8 and trailing LF;
- exact PDD publication workflow identity;
- acceptance of the provisional-only rejection state;
- source predicate hash mismatch;
- non-provisional trust rejection;
- source image digest mismatch;
- publication receipt/PDD content mismatch;
- PDD artifact digest distinctness;
- schema-valid and byte-for-byte deterministic Statement v1 output.

## 6. Acceptance boundary

The implementation is committed to `feat/M4.2.8`, but this step is **not accepted** until local focused tests, full NDF tests, compile/lint checks, pre-commit, actionlint and diff checks pass.

No production workflow, schema, identity policy or publication behavior is changed in this step.
