## 1. Objective

Implement PDD-specific keyless Cosign signing and independent verification for the immutable PDD OCI artifact and its PDD-to-image binding attestation.

## 2. Files added

- `images/ndf/scripts/cosign_pdd_trust.py`
- `images/ndf/schemas/cosign-pdd-binding-statement-v0.1.schema.json`
- `images/ndf/tests/test_cosign_pdd_trust.py`

## 3. Implementation

The utility is intentionally separate from `cosign_image_trust.py`. It reuses its tested low-level Cosign execution, version check, exact certificate-claim argument construction, verified Statement extraction, strict JSON parsing, canonical JSON hashing, signature-output parsing and atomic output writing. Product-image signing and verification behavior is not changed.

### Signing

- Requires an immutable PDD `repository@sha256:<digest>` reference.
- Selects exactly the direct `product-pdd-publication` identity.
- Requires the exact PDD publication workflow on `refs/heads/main` and `workflow_dispatch`.
- Validates the original Statement v1 against the PDD binding schema and exact OCI subject.
- Requires the supplied predicate file to equal the Statement predicate.
- Requires the predicate's workflow claims to equal the actual GitHub Actions runtime context.
- Requires Cosign v3.1.4 before invoking `cosign sign` and `cosign attest`.
- Uses the exact PDD binding predicate URI; it does not use the SLSA alias.

### Verification

- Verifies the PDD signature and binding attestation with exact certificate identity, issuer, trigger, repository and ref; normal Rekor verification remains enabled.
- Extracts exactly one verified Cosign Statement v0.1.
- Validates the strict PDD-specific compatibility schema and then validates the complete binding statement against the canonical PDD Statement v1 schema without changing the verified predicate.
- Requires exact predicate equality with the locally generated expected predicate.
- Derives the source commit from the verified predicate and repeats signature and attestation verification with the exact certificate SHA claim.
- Requires the second verified statement to equal the first.
- Emits a normalized trust result for artifact kind `pdd`, with the exact PDD digest as both signature artifact and attestation subject.
- Writes the cryptographic result as rejected with sole reason `IDENTITY_POLICY_PROVISIONAL` while the policy remains provisional, and raises rather than reporting the result as trusted.

## 4. CLI

Signing:

```bash
python images/ndf/scripts/cosign_pdd_trust.py sign \
  --pdd-ref ghcr.io/ndftechlabs/<pdd-repository>@sha256:<digest> \
  --statement /path/to/pdd-binding-statement.json \
  --predicate /path/to/pdd-binding-predicate.json
```

Verification (producer-side exact-predicate mode):

```bash
python images/ndf/scripts/cosign_pdd_trust.py verify \
  --pdd-ref ghcr.io/ndftechlabs/<pdd-repository>@sha256:<digest> \
  --expected-predicate /path/to/pdd-binding-predicate.json \
  --result-output /path/to/pdd-trust-result.json \
  --attestation-output /path/to/cosign-verified-attestation-output.json
```

The optional `--cosign-bin` argument supports controlled binary selection and tests. The utility itself enforces the exact Cosign version.

## 5. Trust boundaries

This step does not change the identity policy status, publication workflow, consumer fetch workflow, PDD publication receipt, product-image trust implementation or candidate authorization.

The expected-predicate verification mode is for the producer-side publication path. The independent consumer must use self-contained verification without trusting a side-loaded expected predicate; that is M4.2.8.4.5.

No live PDD signing, Fulcio certificate observation, Rekor operation or GHCR publication is claimed by the mocked tests. A real staging-only signing/verification run belongs to M4.2.8.4.4.

## 6. Tests and acceptance boundary

The focused tests cover immutable reference parsing, exact identity and runtime context, signing command construction, validation-before-write behavior, subject/predicate/workflow mismatch, strict v0.1 compatibility, normalized provisional rejection, confirmed-policy result behavior, Cosign version mismatch and command failure.

**Implementation is committed but not accepted** until local focused tests, related trust tests, full NDF suite, compileall, pre-commit, actionlint and diff checks pass.
