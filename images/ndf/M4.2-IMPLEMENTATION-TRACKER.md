### 2026-11-10 — M4.2.2 contract decisions and schema refinement

- Recorded the six contract decisions in `M4.2.2-APPLICATION-DESCRIPTOR.md`: ecosystem-specific version semantics, missing-constraint handling, compatibility evidence, operational dependency dispositions, NDF-controlled policy identifiers, and descriptor filename/identity validation.
- Accepted two validation levels: authoring validation permits incomplete metadata but validates all supplied fields; production eligibility fails closed when required compatibility or dependency metadata is missing, ambiguous or unresolved. An explicit `latest_compatible` selection policy is permitted, but the resolver must later select and lock an exact version. Missing version and missing policy are not treated as a wildcard.
- Refined `dependency-v1.schema.json` with explicit `version_policy` and required/optional package dependency metadata. OS package families and managers are constrained to supported Debian/apt-dpkg, RPM/dnf-yum-rpm and Alpine/apk pairings.
- Refined `marketplace-app-descriptor-v1.schema.json` so verified compatibility requires passed NDF-authority evidence with tested Frappe and Python versions. ERPNext and Node coverage are checked against the descriptor's applicable requirements by the production metadata gate.
- Added SemVer/npm-range parsing using `semantic-version==2.10.0` and PEP 440 parsing using `packaging==25.0`; both dependencies are pinned in `requirements-test.txt`. OS version constraints are deliberately delegated to the target package manager's native solver.
- Added `images/ndf/policies/build-install-policies-v1.json`. Its custom build and installation allowlists are intentionally empty until NDF policies are separately reviewed and implemented. Generic `custom_policy` and `approved_policy` references cannot execute publisher-supplied code.
- Extended `validate_descriptors.py` with supplied-constraint parsing, policy-catalogue checks, OS package-manager pairing checks, production metadata completeness reporting, and canonical descriptor path/filename identity validation. It remains separate from `resolve_manifest.py`.
- Expanded `test_descriptors.py` to 37 test methods covering parser failures/successes, SemVer app release identity, PEP 440 constraints, evidence timestamps and range coverage, authoring versus production metadata readiness, optional dependency selection, base dependency pinning, NDF policy rejection, OS manager pairing, canonical catalogue identity and symlink escape.
