### 2026-11-09 — M4.2.1 source-reference contract correction

- User confirmed that branch references are intentional and may represent production lines; names such as `main`, `master` and `develop` must not be classified as development-only.
- Removed the branch-name classifier and `allow_development_branches` enforcement from the resolver and removed the obsolete field from the manifest schema.
- Replaced branch-name rejection tests with positive coverage for `main`, `master`, `develop` and `version-16` when the reference resolves to a full SHA and compatibility status is verified.
- Clarified that lock `ref` is the resolver's commit observed at resolution time. It is not evidence of the commit acquired later by Bench.
- Confirmed the build contract: M4.2.4 retains upstream `bench init --apps_path` acquisition using requested refs and captures the actual acquired commit inventory; M4.2.5 verifies that inventory against the image; M4.2.6 includes the verified inventory in the digest-bound Product Deployment Descriptor.
- Removed the obsolete `allow_development_branches` setting from the core, product and capability manifests; no application `target_ref` values or compatibility statuses were changed. This changes source-manifest checksums, so existing locks must be regenerated after compatibility evidence is resolved.
- Updated the M4.2 plan, M4.2.1 design record, README and this tracker. M4.2.1 remains In Progress; automated tests have not yet been run. No PR created.
- Feature-branch head immediately before this tracker checkpoint commit: `aec9ec1b1503e50016a1dd583d53520102190916`.
