# M4.2.8.4.4.2 — PDD Publication and Signing Job Contract

**Repository:** `NdfTechLabs/frappe_docker`
**Branch:** `feat/M4.2.8`
**Status:** Partial implementation committed; local validation pending

**Depends on:** Accepted M4.2.8.4.4.1 workflow integration audit

## 1. Objective

Define and implement the first safe publication workflow changes: exact source-image trust artifact intake and least-privilege permission scoping.

The dependent signing job and publication-to-signing artifact are added together with binding generation and Cosign command integration in .4.4.3. Full correlated evidence and provisional-result handling are completed in .4.4.4.

## 2. Existing workflow invariants

The implementation must preserve:

- `workflow_dispatch` as the only trigger;
- publication restricted to `refs/heads/main`;
- exact source build and verification workflow ownership checks;
- source run ID, run attempt and artifact-name correlation;
- current PDD publication receipt schema and artifact name;
- ORAS publication of the PDD and its evidence bundle;
- exact PDD workflow identity used by `cosign_pdd_trust.py`;
- the product-image and candidate workflows unchanged.

No reusable workflow may perform the PDD signing operation because the PDD trust utility requires the direct PDD publication workflow identity.

## 3. Source trust artifact intake

The existing `build_artifact_name` remains the authoritative source for product identity and build attempt. Parse only the exact form:

`ndf-publish-<image_id>-<build_run_id>-<run_attempt>`

Derive the expected source trust artifact name:

`ndf-cosign-live-<image_id>-<build_run_id>-<run_attempt>`

The publication workflow must query the source run's jobs and artifacts and require:

1. The source run is completed successfully, from `ndf-publish-product.yml`, on `main`.
2. The source build artifact belongs to that exact run and attempt and is not expired.
3. The exact `Live Cosign trust check for <image_id>` job completed successfully.
4. The derived `ndf-cosign-live-...` artifact belongs to the same source run, exists and is not expired.
5. The trust artifact contains non-empty `image-provenance-predicate.json` and `cosign-live-verification-result.json`.
6. The source predicate from the trust artifact matches the build artifact's `image-provenance-predicate.json` byte-for-byte.
7. The source trust result is passed to the deterministic binding generator without modification.

The source trust artifact name is derived, not accepted as a second caller-supplied input. This prevents an operator from pairing the build with an unrelated trust result.

## 4. Job permission contract

Workflow-level permissions are restricted to:

```yaml
permissions:
  actions: read
  contents: read
```

The `publish` job explicitly receives:

```yaml
permissions:
  actions: read
  contents: read
  packages: write
```

The `sign-pdd` job explicitly receives:

```yaml
permissions:
  actions: read
  contents: read
  packages: write
  id-token: write
```

Only `sign-pdd` may contain `id-token: write`. The publication job, source intake, binding generation and consumer workflow must not receive OIDC token permission. No job receives `contents: write` or `actions: write`.

## 5. Publication job outputs and signing-input artifact

The publication job remains responsible for upstream run validation, evidence downloads and GHCR PDD publication.

After the publication receipt is written, the job must expose only non-secret correlation outputs needed by the dependent job:

- immutable PDD OCI reference;
- PDD artifact digest;
- attempt-scoped signing-input artifact name.

The publication receipt remains the source of truth. The signing job must download and validate the receipt rather than trusting an output string as proof of the artifact subject.

The publication job uploads one attempt-scoped signing-input artifact containing:

- `pdd-publication-record.json`;
- `pdd-image-binding-statement.json`;
- `pdd-image-binding-predicate.json`.

The existing receipt artifact `ndf-pdd-publication-${build_run_id}-${github.run_attempt}` remains unchanged for compatibility. The new signing-input artifact is separate and is produced only after successful publication and binding generation.

## 6. Signing job dependency and execution boundary

The target `sign-pdd` job is defined here and will be implemented in .4.4.3. It must declare `needs: publish`, avoid `if: always()`, download only a current-run attempt-scoped signing-input artifact, derive the signing subject from the validated receipt's `artifact.immutable_reference`, install pinned Cosign v3.1.4, authenticate to GHCR and invoke the dedicated `cosign_pdd_trust.py` utility.

It must not accept an externally supplied mutable PDD tag, external source SHA or caller-provided expected identity. The utility and receipt determine the artifact identity and predicate content.

## 7. Workflow contract test requirements

Add `images/ndf/tests/test_pdd_publication_workflow_contract.py`.

For .4.4.2, tests statically enforce:

1. Top-level permissions are read-only and contain no `id-token: write` or `packages: write`.
2. The publication job has `actions: read`, `contents: read` and `packages: write` only.
3. No job has `id-token: write` before the signing job is introduced in .4.4.3.
4. The source trust artifact name is derived from the validated build artifact image ID, run ID and attempt.
5. The source trust job and artifact are validated before the source trust artifact is downloaded.
6. Source trust predicate bytes are compared with the build evidence predicate.
7. The original publication receipt artifact name and schema remain unchanged.
8. No product-image workflow, candidate workflow or consumer workflow is modified by this work package.

Use the same static workflow-contract testing style as `test_cosign_live_workflow_contract.py`. Do not rely on executing GitHub Actions or making network calls in unit tests.

## 8. .4.4.2 acceptance criteria

- The source trust result is correlated to the exact source build run and attempt.
- Missing, expired, unsuccessful or mismatched source trust evidence fails closed before PDD binding generation.
- The publication job has only `actions: read`, `contents: read` and `packages: write`.
- No OIDC permission is introduced in .4.4.2; the direct signing job receives it only in .4.4.3.
- The receipt remains the authoritative immutable PDD reference and its existing artifact name/schema remain unchanged.
- The focused workflow contract tests and `actionlint` pass.
- The signer identity remains provisional; no trust policy is changed.
