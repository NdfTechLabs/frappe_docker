# M4.2.8.3.4 — Live Cosign Interoperability and Signer Identity Observation

**Repository:** `NdfTechLabs/frappe_docker`
**Branch:** `feat/M4.2.8`
**Status:** Staging-only workflow integration implemented; local validation and live run pending
**Date:** 15 November 2026
**Depends on:** M4.2.8.2 trust foundation, M4.2.8.3.1 pinned Cosign v3.1.4 toolchain, M4.2.8.3.2 deterministic provenance generation, M4.2.8.3.3 signing and verification utilities

## 1. Purpose

Prove that the pinned Cosign v3.1.4 CLI, GitHub Actions OIDC, Fulcio certificate identity, Sigstore transparency verification, GHCR signature/attestation storage and the NDF verification utility interoperate against one real NDF-owned image digest.

The observation must use the exact workflow identity already reserved by the policy:

`NdfTechLabs/frappe_docker/.github/workflows/ndf-publish-product.yml@refs/heads/main`

A separate smoke workflow has a different certificate identity and cannot, by itself, confirm this product-publication identity.

## 2. Scope and safety boundary

- Use `.github/workflows/ndf-publish-product.yml` on `refs/heads/main` with `workflow_dispatch`.
- Run one explicitly selected product and `linux/amd64`; do not use the `all` matrix.
- Set `publish=false`. This is mandatory. The run must not create or promote the official product source tag.
- Sign only the immutable staging image digest produced and validated by the existing publication gate.
- Use a disposable staging image/tag or a dedicated disposable NDF-owned GHCR repository if the existing workflow cannot guarantee an unused, isolated target. Never overwrite an existing tag.
- Signing must run in a separate job with job-scoped `id-token: write` and the minimum GHCR package permissions required by Cosign. The build/validation job must not receive OIDC token permission.
- Do not grant `contents: write`, `actions: write`, repository administration, or broader permissions.
- Do not weaken the existing candidate actor gate, publication gate, identity matching, transparency verification, or fail-closed behavior.
- Do not sign DT Master-supplied candidate artifacts. NDF signs only the image digest produced by its own validated build.
- Do not enable production trust-gated promotion in this package.

## 3. Workflow design requirements

The implementation may add a dedicated staging-only signing job to the existing product publication workflow, but it must preserve the workflow path and caller identity above.

The build/validation job must:
1. Build and push the unique staging image as it does today.
2. Complete image validation and the existing publication gate.
3. Generate the deterministic SLSA Provenance v1 predicate and complete in-toto Statement using the exact build evidence.
4. Upload the complete build-output directory under the existing run/attempt-scoped artifact name.

The signing job must:
1. Depend on successful build/validation and consume only the matching run/attempt artifact.
2. Re-read the build metadata and build result to derive the immutable repository@digest reference; it must not accept a tag or caller-supplied digest.
3. Install and enforce Cosign v3.1.4.
4. Have `id-token: write` and only the registry permissions required to attach the signature and attestation. The build/validation job must not receive OIDC permission.
5. Invoke `cosign_image_trust.py sign` against the immutable digest with the predicate and Statement generated by the build job. The utility must cross-check the exact subject repository/digest and workflow metadata.
6. Independently invoke `cosign_image_trust.py verify` against that same digest and capture the normalized result even when the provisional policy correctly causes the final trust decision to be rejected.
7. Upload the Cosign verification output and normalized result as evidence. Do not publish secrets or raw OIDC tokens.

The signing job must not trust a mutable tag, caller-provided digest, unverified artifact path, or a result from a different run attempt. It must fail if the expected build artifact is absent, ambiguous, or inconsistent.

## 4. Provisional identity observation

The current policy status is `provisional_until_live_certificate_observation`. It must remain provisional during the first live run.

The live run must establish all of the following from actual Cosign operations:
- Cosign v3.1.4 installed and used;
- OIDC token acquisition succeeds in the signing job;
- image signature is attached to the exact immutable staging digest;
- SLSA Provenance v1 attestation is attached to the same digest;
- Fulcio certificate identity equals the exact product-image identity entry;
- OIDC issuer equals `https://token.actions.githubusercontent.com`;
- trigger, repository, ref and source SHA claims match the run;
- Rekor inclusion proof and normal Sigstore trusted-root verification succeed;
- Cosign v3.1.4 verification output can be decoded by the NDF utility;
- the verified Statement passes the NDF schema and exact subject digest/repository/workflow checks.

A verifier result rejected solely because the policy is still provisional is expected during this observation. It must not be converted into `trusted` and must not authorize promotion.

After collecting evidence, compare the observed certificate identity and claims with the exact policy entry. If any claim differs, stop and revise the policy only through a separately reviewed, evidence-backed change. Do not use a wildcard or regex fallback.

Changing policy status to `confirmed` is a separate decision after the evidence has been reviewed; it is not an automatic side effect of a successful workflow.

## 5. Required evidence record

Retain, with run ID and run attempt:
- source commit and workflow ref;
- product ID, platform, staging repository and immutable image digest;
- SHA-256 hashes of predicate and Statement;
- Cosign version output;
- signing command outcome for image signature and attestation;
- verification command outcomes and their exact certificate identity/issuer constraints;
- exact certificate identity, issuer and GitHub certificate-extension constraints passed to Cosign, plus successful verification under those exact constraints; do not publish OIDC tokens or credentials;
- proof that transparency verification was enabled and succeeded;
- normalized NDF verification result and its reason codes;
- confirmation that `publish=false` and no official product tag was created.

The evidence record must not contain OIDC tokens, GitHub credentials, registry passwords or other secrets.

## 6. Acceptance criteria

M4.2.8.3.4 is accepted only when:
1. A real GitHub Actions run from the exact product workflow on `main` completes the staging-only build and validation path.
2. The signing job receives OIDC permission while the build/validation job does not.
3. Cosign v3.1.4 signs the exact immutable image digest and attaches the SLSA provenance attestation.
4. Independent Cosign verification succeeds with exact identity, issuer, trigger, repository, ref and source-SHA constraints, and normal transparency verification.
5. Cosign verifies the actual Fulcio certificate against the exact identity, issuer, trigger, repository, ref and source-SHA constraints in the current policy entry; the successful verification and exact constraints are retained as evidence.
6. The NDF verifier parses the actual Cosign output and validates the full Statement and exact subject binding. A provisional-policy rejection is expected and recorded; no trusted decision is emitted until a separate policy confirmation.
7. No official product tag is created or promoted.
8. The live evidence is documented and reviewed before any policy confirmation or production promotion integration.

## 7. Explicitly out of scope

- Changing the signer policy to `confirmed` automatically.
- Trust-gated official product promotion.
- Signing or verifying PDD OCI artifacts.
- Candidate image/PDD reusable workflow identities.
- DT Master candidate artifact signing.
- Release workflow changes or general-purpose trust rollout.
- Any bypass of Rekor, Fulcio, certificate identity, publication or candidate authorization checks.

## 8. Implementation checkpoint

Implemented on `feat/M4.2.8`:

- Added deterministic provenance generation after the existing publication gate in `.github/workflows/ndf-publish-product.yml`.
- Added a separate `sign-trust` job. Only this job receives `id-token: write`; the existing build/validation job retains its previous permissions.
- The live signing job is restricted to `workflow_dispatch` on `refs/heads/main`, one explicitly selected product (not `all`), and `publish=false`.
- The signing job downloads only the matching product/run/attempt build artifact, derives the immutable GHCR digest reference from build metadata/result, installs Cosign v3.1.4, signs the image and SLSA provenance, and independently verifies both.
- The verifier's expected nonzero exit is accepted only when the normalized result proves signature, signer, transparency and attestation verification succeeded and the sole decision reason is `IDENTITY_POLICY_PROVISIONAL`.
- The signing job uploads the predicate, Statement, verification log and normalized result. It contains no promotion step. The existing official promotion step remains guarded by `inputs.publish`.
- Added `images/ndf/tests/test_cosign_live_workflow_contract.py` for permission isolation, ordering, run/attempt-scoped artifact use, exact tool pin, immutable digest use, provisional rejection and no-promotion boundaries.
