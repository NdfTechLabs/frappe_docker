## 3. Implementation and diagnostic history

The first live run (43749475694) built and signed the staging image but exposed an NDF decoder defect after Cosign verification. Run 43751942157 added raw verified-attestation output capture; the same decoder failure then exposed the actual Cosign v3.1.4 output format.

Source inspection established that the `slsaprovenance1` alias uses a specialized SLSA protobuf conversion path that drops the NDF `ndf_build` extension. The explicit predicate URI `https://slsa.dev/provenance/v1` selects Cosign's generic JSON path and preserves the supplied predicate. That generic path emits an in-toto Statement v0.1 wrapper.

M4.2.8.3.5 corrected the implementation without weakening the NDF contract:

- The canonical NDF producer continues to emit and validate Statement v1.
- Cosign signing and verification use the explicit SLSA Provenance v1 predicate URI, not the `slsaprovenance1` alias.
- A separate strict Statement v0.1 compatibility schema validates the Cosign wrapper.
- The decoded predicate must equal the original NDF predicate exactly, including every `ndf_build` claim.
- A version-normalized copy is validated against the canonical NDF Statement v1 schema; the verified payload itself is not rewritten.
- Subject repository/digest, predicate type and exact workflow identity checks remain mandatory.
