# M4.2.6.5 — Product Deployment Descriptor Image and Evidence Binding

**Status:** Implementation in progress  
**Branch:** `feat/M4.2.6`  
**Descriptor contract:** PDD v1  
**Evidence contract:** M4.2.5 image-verification-evidence-v1  
**Next package:** M4.2.6.6 — Publication and Consumption Contract

## 1. Purpose

Independently prove that a PDD's eleven evidence records identify the exact evidence-file bytes supplied for the build and that the immutable OCI image reference resolves to the exact digest recorded by the descriptor.

M4.2.6.4 validates the descriptor's schema, integrity and internal relationships. This package closes the external binding gap: file bytes, build sidecars, lock-v2, verification reports and the registry manifest must all agree.

## 2. Inputs

The verifier accepts:
- A serialized PDD v1 descriptor.
- An evidence directory containing the eleven files referenced by the descriptor.
- The M4.2.5 `image-verification-evidence.json` binding manifest.
- Build sidecars: `build-result.json`, `build-metadata.json`, `buildx-metadata.json`, and `image-validation.json`.
- The immutable OCI reference from `artifact.immutable_reference`.

The ten ordinary evidence paths are resolved relative to the evidence directory. The PDD's logical lock path is `lock-v2.json`; the physical lock file is resolved using the authoritative build-result image ID as `<image-id>.lock-v2.json`, matching the existing generator/build artifact contract. The descriptor is not modified.

The implementation is in `scripts/verify_product_deployment_binding.py`, with adversarial coverage in `tests/test_verify_product_deployment_binding.py`. Invoke it with:

```bash
python images/ndf/scripts/verify_product_deployment_binding.py \
  --descriptor /path/to/product-deployment.json \
  --evidence-dir /path/to/build-output
```

The command emits a JSON result and exits non-zero on any validation or binding failure.

## 3. Required checks

1. Run the independent M4.2.6.4 validator before binding.
2. Enforce safe relative paths, path containment, no symlink traversal, regular files, no duplicate paths and no missing records.
3. Hash exact file bytes with SHA-256 and compare both digest and byte size against every PDD evidence record.
4. Independently validate the M4.2.5 evidence-manifest structure and compare its complete eleven-record inventory against the PDD and actual bytes.
5. Cross-check the image digest, repository and image ID across the descriptor, build result, build metadata, Buildx metadata, image-validation report and evidence manifest.
6. Recompute the exact lock-v2 byte digest. Require agreement with PDD composition identity, build metadata, build inventory, build-evidence report and image-verification evidence.
7. Recompute the build-inventory byte digest and compare it with the build-evidence report.
8. Require source-provenance, post-cleanup source-tree, runtime source-tree and image-composition verification reports to report `passed`; require the composition report to bind to the exact lock-v2 digest.
9. Resolve the immutable `repository@sha256:digest` through the registry using `docker buildx imagetools inspect --raw`. Hash the exact raw OCI manifest bytes and require equality with the descriptor digest. Command errors, empty output or digest mismatch fail closed.
10. Emit deterministic machine-readable success/failure JSON with descriptor identity, image digest, evidence count and completed binding checks.

## 4. Security and failure behavior

- Never follow symlinks from evidence paths.
- Reject path traversal, absolute paths, duplicate evidence names/paths and non-regular files.
- Do not trust tags as immutable identities; registry verification uses the descriptor's digest-pinned reference.
- Do not accept a caller-supplied digest as a substitute for querying the registry.
- Do not normalize or reserialize evidence before hashing. Hash exact bytes.
- Do not rewrite the PDD or evidence artifacts.
- Any missing, malformed, ambiguous, mismatched or unverifiable input returns a non-zero exit status.

## 5. Test plan

Positive coverage:
- Complete synthetic evidence directory and sidecars accepted.
- Exact registry manifest bytes resolve to the descriptor digest.
- Paths containing safe nested directories accepted.
- Machine-readable CLI success report.

Adversarial coverage:
- Missing evidence, changed bytes, changed byte size, wrong path, duplicate path and duplicate evidence name.
- Absolute paths, parent traversal, symlink escape and non-regular file.
- PDD/evidence-manifest inventory mismatch.
- Image digest/repository/image-ID mismatch across every sidecar.
- Lock-v2, build inventory or build-evidence hash mismatch.
- Failed or mismatched independent verification reports.
- Missing/invalid immutable reference.
- Registry command failure, empty manifest and manifest digest mismatch.
- CLI failure report and non-zero exit.

The test suite uses synthetic fixtures and mocks only the external registry command boundary. The focused and full NDF test suites must pass locally. At least one real registry-backed verification is required for operational acceptance.

## 6. Scope boundaries

Included: exact PDD evidence-file byte binding, M4.5 evidence-manifest cross-checks, build/lock/image identity reconciliation, registry OCI manifest digest verification, structured report and adversarial tests.

Excluded: descriptor publication/retrieval, stable channel/tag policy, candidate workflows, official image promotion, signatures/attestations, deployment orchestration and changes to the PDD schema or evidence-name contract. These belong to M4.2.6.6, M4.2.7, M4.2.8 and later integration work.

Unobserved service execution topology, storage, networking, health/readiness, operations and infrastructure requirements remain explicit gaps. This package must not invent them.


## 7. Implementation checkpoint — 14 November 2026

The first implementation slice is committed on `feat/M4.2.6`:

- `scripts/verify_product_deployment_binding.py` independently invokes the M4.2.6.4 validator, reopens and hashes all eleven evidence files, validates the M4.2.5 evidence-manifest schema and inventory, reconciles build/lock/image identities, checks verification report states and queries the digest-pinned registry reference for the raw OCI manifest.
- The logical PDD lock evidence path `lock-v2.json` is resolved to the physical `<image-id>.lock-v2.json` build artifact using the image ID from `build-result.json`.
- Evidence and sidecar paths reject symlinks; evidence paths reject traversal and escaping paths. Registry inspection has a bounded timeout and fails closed on command errors, empty output or digest mismatch.
- `tests/test_verify_product_deployment_binding.py` adds synthetic positive coverage and adversarial cases for byte tampering/size mismatch, missing files, symlinks, evidence-manifest mismatch, sidecar identity/platform/digest mismatch, failed verification reports and registry failures/digest mismatch.

**Validation status:** implementation checkpoint only. User-run focused tests, full NDF regression, compilation, pre-commit and a real registry-backed check remain pending. No M4.2.6.5 acceptance claim is made yet.
